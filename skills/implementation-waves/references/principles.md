# Source principles

## Walking Skeleton and Elephant Carpaccio

- [Walking Skeleton](https://alistaircockburn.com/Bio): Alistair Cockburn describes it as a thinly connected functioning architecture.
- [Elephant Carpaccio](https://alistaircockburn.com/Elephant-Carpaccio): divide a problem into many small growth stages that reduce risk and create learning points.
- [Software Carpaccio exercise](https://alistair.cockburn.us/wp-content/uploads/2018/02/Elephant-Carpaccio-exercise-instructions.pdf): use short build-and-demo rounds with real observable input and output.

## Tracer Bullets and evolutionary design

- [Pragmatic Programmer tips](https://pragprog.com/tips/): use Tracer Bullets to find the target by implementing, observing, and adjusting.
- [YAGNI](https://martinfowler.com/bliki/Yagni.html): avoid presumptive capability while keeping the system easy to change.
- [Is Design Dead?](https://martinfowler.com/articles/designDead.html): grow design through simple implementations, testing, continuous integration, and refactoring.

## Verification and small batches

- [Test-Driven Development](https://martinfowler.com/bliki/TestDrivenDevelopment.html): add one behavior, make it work, then improve its structure.
- [DORA DevOps capabilities](https://docs.cloud.google.com/architecture/devops): small batches shorten lead time and feedback loops.
- [Principles behind the Agile Manifesto](https://agilemanifesto.org/principles): deliver working software frequently and use it as the primary measure of progress.
